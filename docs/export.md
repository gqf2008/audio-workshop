# 导出：单篇 / 批量 / 分轨

> 2026-09-17。对应 thread `cc-ai-audio-workshop-stem-export`。
> 产品口径：`docs/product-plan.md` §4.2 的 **P6「分轨 / 批量导出」**。

导出目录固定为 `export_dir()`（系统文档目录下的「音频作坊/export」，界面上的导出目录输入框
是只读的）。三条导出路径都在 `src/export.rs`，**复制语义只有一份**（`copy_atomic` +
`export_one` / `export_stem` / `export_stems`）。

## 1. 三条路径

| 路径 | 入口 | 导出什么 | 源 |
|---|---|---|---|
| 单篇 | 导出行「导出」（或拼装完成时自动） | `<工程名>.wav` / `.srt`（按格式开关） | 当前工程 `out/final.wav` + `out/final.srt` |
| 批量 | 导出行「批量导出」 | 每个有成品的工程各一份 `<工程名>.wav` / `.srt` | 扫 `projects/` 下所有 `out/final.wav` |
| 分轨 | 导出行「分轨导出」；BGM 页每轨的「导出」 | `<工程名>_voice.wav` + `<工程名>_bgm.wav`（BGM 页还可单独导 `_mixed.wav`） | 磁盘上的 `out/voice.wav`（退回 `out/final.wav`）/ `bgm/bgm.wav` / `out/mixed.wav` |

分轨的命名是**既有约定**（BGM 页逐轨导出一开始就用 `_voice` / `_bgm` / `_mixed`）：
同一轨不能因为从哪个按钮导出就换个名字，否则导出目录里会出现同一内容的两份文件。
两条路径共用 `export_stem`，来源与命名只有一处。

## 2. 为什么分轨从磁盘解析，而不是内存里的 `BgmArtifacts`

`bgm/bgm.wav`、`out/voice.wav`、`out/mixed.wav` 都是落盘产物。只认本次会话的内存状态，
会让「昨天混好的分轨，今天重开应用就导不出来」。所以 `stem_source` 一律看磁盘：

- 人声轨：`out/voice.wav` → 退回 `out/final.wav`（没混过音的工程，配音成品本身就是人声轨）；
- BGM 轨：`bgm/bgm.wav`；
- 混音轨：`out/mixed.wav`。

缺哪一轨就如实说哪一轨，而且**下一步指向不同的页面**：缺人声 →「先完成配音合成」，
缺 BGM →「先在 BGM 页生成」（本机真实工程里就有"只有 BGM、没人声"那种，套用一句
统一提示会指错路）。**缺一轨不算整次失败**——用户要的是"拿到有的那轨 + 知道缺什么"。

## 3. 与"正在写成品"的任务互斥

导出**不经过 worker、不进任务台账**：它只读磁盘上已经写好的文件，读的时候不会读到半截
（这些文件都是「临时文件 + fsync + rename」原子写出来的）。但有两件事必须挡住：

1. `assemble` 是**先发布 `final.wav`、再写 `final.srt`**：中间那一瞬导出会拿到
   **新 WAV 配旧 SRT**（或把新工程误报成"缺字幕"）；
2. 分轨的源（`out/voice.wav` / `out/mixed.wav` / `bgm/bgm.wav`）是 BGM 混音写出来的，
   混音跑到一半导出去就是半套。

写这些产物的动作都有在飞标志——单篇拼装/导出、BGM 生成、重录、试听走 UI 的 `busy`；
批量 worker 每篇的拼装走 `batch_in_flight`。判据统一在
`export_refusal(ui_busy, batch_in_flight)`，界面上的按钮也一起置灰（不只靠回调拒绝）。

**能力边界（别读错）**：单篇**逐句合成**期间可以导出（读到的是上一次拼装的成品，原子写
不会是半截）；**批量任务运行期间批量导出会拒绝**——批量会一路拼装写成品，正是被挡的那类
写者。

## 4. 失败与边界

- 单篇：未选格式 → 明确报「未选择导出格式」，不建目录；缺字幕（勾了 SRT）→ 按是否勾了
  WAV 分两种文案（勾了说"只导出了 WAV"，没勾说"什么都没导出"）。
- 批量：失败隔离（某篇缺字幕只让那篇失败，其它照常导）；`total = exported + failures.len()`；
  没成品的目录不算候选、不算失败。
- 扫描边界：工程目录不存在 / 读不出来要报错（不与"目录里没有成品"共用一句话）；
  目录名必须是 UTF-8（`to_string_lossy` 会把两个不同的非法名字压成同一个名字，互相覆盖）；
  不跟符号链接（否则能把工程目录之外的内容导出去）。
- 重复导出即覆盖（`copy_atomic` 原子替换）；临时文件名是「目标名 + `.tmp<pid>-<序号>`」，
  同一进程里的并发复制不会抢同一个 `.tmp`。
