# 发音词典库：多套词典 + 词条批量导入导出（M4-P5）

> 2026-09-17 首版。对应 thread `cc-ai-audio-workshop-dictionary`。
> 产品口径：`docs/product-plan.md` §4.2 的 **P5「发音词典库（多套）」**。

## 1. 它解决什么

`aw_core::apply_dictionary` 早就有，但桌面端三处调用全传空词典——**词典功能等于没接**。
现在配音页「高级」里有「词典」一行：选一套启用（或"不使用"）、导入词条、导出词条。

```text
~/Documents/音频作坊/dictionaries/
  口播专用-3ab41c7d.json    # {"name":"口播专用","entries":{"重庆":"崇庆"},"updated_at":…}
```

当前启用的那一套记在 `settings.json`（重启仍在）。库内文件名的唯一性与路径安全沿用音色库
复核实修的那几条：slug + 名字哈希后缀（不同名字不会撞同一文件）、文件名白名单、拒绝软链、
**写新文件 → 落盘成功 → 才清理旧文件**。

## 2. 词典怎么生效

词典进的是**文本层**（`new_project_from_inputs` 里的 spoken 文本）：

- 开「数字/年份规范化」时：`aw_core::normalize(t, dict)`（先词典、后数字规则）；
- 关掉数字规范化时：仍然 `apply_dictionary(t, dict)`——**词典是"这个词怎么念"，与数字规则是
  两件事**，关兜底不等于把词典也关了。

词典指纹（`dict_hash`）会写进 `project.json`，并且是续作复用门槛的一部分：
**换词典 = 改 spoken 文本 → 旧音频一律不复用**（与换模型、换兜底开关同类）。
不这么做的话，成品里会留着旧读法而界面显示新词典。

## 3. 词条批量导入导出

- **导入**：选一个 `.tsv` / `.csv` / `.txt`，每行 `词条<分隔>替换`，分隔支持 **Tab / 逗号 /
  等号 / 全角等号**；去 BOM、CRLF 归一为 LF；空行与 `#` 注释跳过。导入前先校验文件体积
  （>2MB 拒绝）与 UTF-8；每行的问题都会带上行号说明（认不出分隔符 / 一侧为空 / 超过 64 字）；
  同一个词条重复时**后出现的覆盖前面的**，并提示"第 N 行已定义，以本行为准"。
  导入结果落在**当前启用的那套词典**里；没启用就按文件名找同名词典（**合并**进去，不会因为
  "同名覆盖"丢掉原词条），没有同名才新建一套；导入完自动启用。
- 分隔符取**行内最早出现**的那个：`重庆,桥=大桥` 会切成 `重庆` → `桥=大桥`（替换文本里的
  等号要保留），而不是按"先 Tab 再等号"的优先级切错。
- 词条指纹用**长度前缀**再哈希：直接拼 `k=v\n` 会让 `{"a=b":"c"}` 与 `{"a":"b=c"}` 同指纹，
  换词典时就可能错误复用旧音频。
- **导出**：把当前启用的一套写成 `<导出目录>/dict-<名字>.tsv`（`词条<Tab>替换`，首行是注释），
  编辑后再导入即可。

## 4. 已知边界（v1）

- 界面只做"选一套 / 导入 / 导出"，**不做逐条编辑**：要精修就导出成 TSV 改完再导入（词条动辄
  几百条，表格工具比文本框合适）。
- 不做删除词典（与音色库同理：直接删 `dictionaries/` 下的文件）。
- 不做词条级"只对某句生效"的范围控制；词典是整套生效。
- 任务在飞（含批量）时词典区锁住：批量提交那一刻词典已定，中途换会出现"界面显示新词典、
  那批仍按旧词典跑"。导入的文件框是异步的，**回调到达时会再查一次**任务状态，过期就丢弃。
- 启用的那套词典被删/读不出来时，界面会退回「不使用词典」并**清掉内存里的词条**，
  不会出现"界面没启用、合成还在用旧读法"。

## 5. 与其它资产的关系

- 词典属于**文本层**，与音色/模型正交：换词典不改音色，换音色不改读法；
- 工程版本存的是稿件与设置，**词典用"当前启用的那套"**——版本不带词典走（词典是库资产），
  但 `dict_hash` 会参与回滚时的音频复用判定，所以不会出现"显示新词典、听着旧读法"。
