# 音色库：多音色的保存 / 应用 / 导入导出（M4-P4）

> 2026-09-17 首版。对应 thread `cc-ai-audio-workshop-voice-library`。
> 产品口径：`docs/product-plan.md` §4.2 的 **P4「音色库（多音色）」**。

## 1. 它解决什么

在此之前，工程的音色只是一个**外链路径**（`voice_ref`）：参考音频一挪、一删、一改名，
工程就废了，也没法把辛苦调好的音色留到下一个工程用。音色库把音色变成**自包含条目**：
保存时把参考音频**复制进库**，条目自己就能用。

## 2. 存在哪

```text
~/Documents/音频作坊/voices/
  index.json        # 条目元数据：名字 / 文件名 / 备注 / 入库时间
  口播男声.wav       # 参考音频副本（自包含）
```

- 名字在库内唯一（**忽略大小写**），同名保存 = 覆盖（音频也一起换）；
- 库内文件名 = `归一后的名字 + 名字哈希后缀`（如 `口播男声-3ab41c7d.wav`）：只用归一后的名字
  会让 `a/b` 与 `a_b` 落到同一个文件、互相覆盖（复核指出的反例），加哈希后同名的文件稳定、
  不同名不会撞。导出目录名同理；
- 保存顺序是"**先读索引 → 写一个全新的音频文件 → 索引落盘成功 → 才清理被替换的旧文件**"：
  每次保存都用新文件名（同名也换新文件），所以索引写失败时旧资产一个字节都没动，只会留下
  一个没被引用的哑文件；清理前还要过 "裸文件名 + 库内普通文件" 的校验——旧条目来自
  `index.json`，手改成 `../重要.txt` 后清理就会删到库外（这是复核抓到的数据安全阻塞）；
- 库里/导入包里的音频必须是**普通文件**：符号链接（可能指向库外）一律拒绝；
- 文件名走与工程名同一套归一（`file_stem`），避免非法字符；
- 索引是原子写；索引读不出来时界面会**明确报"音色库读不出来"**而不是显示空库
  （空库会让用户以为音色丢了，甚至下一次保存把索引覆盖掉）；
- 保存时校验：文件存在、扩展名在 wav / mp3 / flac / m4a / ogg 之内、非空、
  wav 还要能解析——坏音频在入库前就会被挡下并给出可执行文案。

## 3. 四个动作

| 动作 | 做什么 | 备注 |
|---|---|---|
| 存入音色库 | 把当前参考音频复制进库（同名覆盖） | 备注可选；原文件删了也能用 |
| 应用 | 把工程的参考音频换成库里的副本 | **需要重新合成**（换音色 = 换发声身份，与手工改参考音同一条作废路径） |
| 导出 | 写到 `<导出目录>/voice-lib/<音色名>/`：`voice.json` + 音频 | 拷走这个目录即可跨机 |
| 导入… | 选一个导出目录（含 `voice.json` + 音频）收进本机库 | 清单里的音频名**只允许裸文件名**（`../x.wav` 这类会被拒绝） |

导入导出走的是同一份 `VoiceEntry` 清单，所以"导出 → 导入"回来的是同一条目（名字、备注、
音频字节都一致，有单测）。

## 4. 已知边界（v1）

- **不做删除**：音色是用户资产，删除是破坏性操作。要清理就直接删 `voices/` 下的音频与
  `index.json` 里对应条目（文档写在这里，界面上不放删除按钮）。
- 不做"改备注/改名"的原地编辑：改名字等于新建一条（同名才覆盖）。
- 不做云同步；跨机走导出目录（U 盘 / 网盘由用户自己搬）。
- 批量任务在跑时音色区整体锁住（批量提交那一刻 `voice_ref` 已定格，中途换音色会"界面显示 A、
  批量按 B 跑"）。
- 导入是**按清单收音频**，不是"指向原机器路径"——这是刻意的：指向别机路径的音色在新机器
  上必然不可用。

## 5. 与工程、模板的关系

- 应用音色 = 改工程的 `voice_ref`，因此与"手工填参考音"完全同源（作废 + 需重录）；
- 音色库条目**不绑定模型**：同一个音色可以配不同引擎试（模型是引擎参数，音色是发声身份——
  这条区分来自早前的用户纠偏）；模板里存的音色是"当时的参考音频路径"，与库条目互不影响。
