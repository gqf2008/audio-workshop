# 音色克隆（参考音频 + 参考文本）

## 这是什么

「音色克隆」= 拿一段干净人声做参考，让 TTS 用**那个声音**念你的稿子。
配音页「换音色 → 参考音频」、以及「音色设计」Tab，填的都是这同一份输入。

## 服务端的硬要求：音频与文本**成对**

本机 audio.cpp 的 TTS 模型（`audio8-tts` 等）在收到 `voice_ref`（参考音频路径）时，
**必须同时**收到 `reference_text`——即这段参考音频里**实际念的内容**。少了它服务端直接拒绝：

```
HTTP 500 Audio8 TTS prepare with inline reference audio requires reference_text option
```

真机三连（同 seed、同文本、参考音 = 示例工程的 `stems/*_vocals.wav`）：

| 请求 | 结果 |
|---|---|
| 不带 `voice_ref` | 200（内置音色） |
| 带 `voice_ref`，不带 `reference_text` | **500**（上面那条） |
| 带 `voice_ref` + `reference_text` | 200，**音色确实不同**（产物 sha256 与字节数都变） |

修复前 `synth` 只发 `voice_ref`，于是**每一句都 500**、整轮配音全红——而界面上连
「参考文本」这个输入框都没有。现在：

- `aw_core::VoiceClone` 把两者**绑成一个类型**，`synth` 无法只收到路径；
- 文本为空时在**发起前**就拦住（一次可执行的提示，而不是 N 句一样的失败）；
- UI 有「参考文本」输入框 + 「自动转写」按钮。

## 参考文本从哪来

1. **自动转写**：点「自动转写」，本机 ASR（默认 `qwen3-asr`）听一遍参考音频、
   把结果**填进输入框**。
2. **手动核对/修改**：填进去的结果是给你改的，不是替你拍板的。**请务必核对**——
   转写错字会让克隆出来的音色跑偏（服务端拿这段文本做条件）。
3. **直接手填**：不用 ASR 也行，自己把这段音频念的内容写进去。

自动转写失败（服务不可达 / 内存不够加载 ASR 模型）时，状态行给的是**模型名 + 原因 +
"可以手填"**——手填这条路不依赖任何模型，永远可用。

## 改动会作废什么

参考音路径、参考音**内容**（哈希）、参考**文本**，三者任一变了都算"换了音色"：

- 旧音频不复用（`settings_allow_reuse` 三样一起比，worker 与版本回滚共用这一条）；
- 版本差异里会显示「音色」变了（内容变了标「内容已变」，只改文本标「参考文本已改」）；
- 模板会把参考文本一起存（只存路径的模板应用回来是个跑不起来的克隆）。

这条不是洁癖：不把文本算进音色身份的话，"让用户核对转写"就成了空转——改完文本点合成，
句子都是 `done` 被直接复用，用户听到的还是旧转写合成的声音。

## 明确不做（v1 边界）

- **不改服务端**，不做多参考音（`multi_reference_cond`）。
- 不做 `index-tts2` 的专用参数；它同样要求参考音，走的是同一条路。
- 「文本描述生成音色」已接入（`qwen3_tts` 的 `voice_design` 任务：试听文本 + 音色描述 →  `options.voice_design`）；本条只讲「参考音频克隆」这一条。
- 转写**不做模型自动降级**：用 `DEFAULT_ASR_MODEL`，失败就如实报模型名 + 原因。
  （质检那条链路的模型选择是另一件事，见 `docs/quality-check.md`。）
