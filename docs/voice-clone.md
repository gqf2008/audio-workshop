# 音色克隆（参考音频 + 参考文本）

## 这是什么

「音色克隆」= 拿一段干净人声做参考，让 TTS 用**那个声音**念你的稿子。
配音页「换音色 → 参考音频」、以及「音色设计」Tab，填的都是这同一份输入。

## 参考音频时长：5–30 秒是**硬上限**

上限 30 秒，超过会在**发起任何请求之前**被拦下（状态行给出实际秒数与处理建议）。
这不是产品洁癖，是引擎的内存安全边界（2026-09-22 真机复现）：

- 192.9s 参考音发 audio8-tts 克隆 → 引擎按参考时长膨胀图尺寸，向 Metal 申请
  **14,539 MiB** buffer → 分配失败 → `ggml_metal_buffer_is_shared` 空指针
  **SIGSEGV，整个引擎进程死掉**；
- 同一文件裁到 20s → HTTP 200，11.3s 出音频；
- 分配规模约 **75 MiB/参考秒**：30s ≈ 2.3 GiB，仍在常见机器的安全余量内。

护栏的实现口径（`aw_core::ref_audio`，只此一份判据）：

- wav 读 RIFF 头拿时长；mp3/flac 等用 symphonia 探测（与分离链路同一读头依赖）；
- **读不出时长 → fail-open 放行**（文件损坏/不支持的容器如 m4a/VBR mp3 头里没有
  帧数）：最坏结果与没有护栏一样，而 fail-closed 会把"探测坏了"放大成"克隆不可用"；
- 拦截覆盖所有会发克隆请求的入口：开始合成 / 批量提交 / 单句重录 / 音色试听；
- 配音页与音色设计 Tab 选中参考音频后都会显示时长，超限显红色警告。

## 参考文本是**按引擎**的要求（不是全局硬要求）

本机 audio.cpp 的 TTS 模型逐模型声明要不要参考文本（上游 `model_specs/*.json` 的
`options.request`）：

| 引擎 | 只给 `voice_ref`、不给 `reference_text` | 结论 |
|---|---|---|
| audio8-tts / audio8-tts-01b / -stream 变体 | HTTP 500 `Audio8 TTS prepare with inline reference audio requires reference_text option` | **必填**：克隆路径要求音频与文本成对 |
| index-tts2 | **HTTP 200**，正常出音频 | **可选**：不需要参考文本 |
| f5 / glm / breeze（上游 spec） | spec 声明 `reference_text`（部分标 `required: true`） | 按 spec 必填 |
| qwen3-tts（vdes 音色设计） | 不走克隆路径 | 不适用 |

真机三连（同一条 8s 参考音频、同 seed、同文本）：

| 请求 | audio8-tts | index-tts2 |
|---|---|---|
| 不带 `voice_ref` | 200（内置音色） | 500（该引擎必须参考音） |
| 带 `voice_ref`，不带 `reference_text` | **500**（上面那条） | **200**，正常出音频 |
| 带 `voice_ref` + `reference_text` | 200，**音色确实不同**（产物 sha256 与字节数都变） | 200 |

修复前 `synth` 只发 `voice_ref`，而界面上没有「参考文本」输入框 —— audio8-tts 用户
**每一句都 500**、整轮配音全红。现在：

- 引擎要求按**能力清单**声明（`config/models.schema.yaml` 的 `requires.reference_text`，
  随包进 `config/model-capabilities.json`，服务端显式值优先）；
- `aw_core::VoiceClone` 只守"路径非空"这个类型不变式；空文本由 `build_synth_request`
  **连字段都不发**（发空串与"没给"不是一回事）；
- 文本必填的引擎（audio8-tts 等）在**发起前**就拦住（一次点名的提示：点「自动转写」
  或换不要求文本的引擎）；可选引擎（index-tts2）直接提交；
- UI 有「参考文本」输入框 + 「自动转写」按钮，占位/必填提示/红色告警都按选中引擎显示。

## 参考文本从哪来

1. **自动转写**：点「自动转写」，本机 ASR（默认 `qwen3-asr`）听一遍参考音频、
   把结果**填进输入框**。
2. **手动核对/修改**：填进去的结果是给你改的，不是替你拍板的。**请务必核对**——
   转写错字会让克隆出来的音色跑偏（服务端拿这段文本做条件）。
3. **直接手填**：不用 ASR 也行，自己把这段音频念的内容写进去。

自动转写失败（服务不可达 / 内存不够加载 ASR 模型）时，状态行给的是**模型名 + 原因 +
"可以手填"**——手填这条路不依赖任何模型，永远可用。

## 改动会作废什么

参考音路径、参考音**内容**（哈希）、参考**文本**，三者任一变了都算"换了音色"：

- 旧音频不复用（`settings_allow_reuse` 三样一起比，worker 与版本回滚共用这一条）；
- 版本差异里会显示「音色」变了（内容变了标「内容已变」，只改文本标「参考文本已改」）；
- 模板会把参考文本一起存（只存路径的模板应用回来是个跑不起来的克隆）。

这条不是洁癖：不把文本算进音色身份的话，"让用户核对转写"就成了空转——改完文本点合成，
句子都是 `done` 被直接复用，用户听到的还是旧转写合成的声音。

## 明确不做（v1 边界）

- **不改服务端**，不做多参考音（`multi_reference_cond`）。
- 不做 `index-tts2` 的专用参数；它同样要求参考音，走的是同一条路。
- 「文本描述生成音色」已接入（`qwen3_tts` 的 `vdes` 任务：试听文本 + 音色描述 →  `options.instruction`）；本条只讲「参考音频克隆」这一条。
- 转写**不做模型自动降级**：用 `DEFAULT_ASR_MODEL`，失败就如实报模型名 + 原因。
  （质检那条链路的模型选择是另一件事，见 `docs/quality-check.md`。）
