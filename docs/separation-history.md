# 人声分离历史（v1）

> 对应功能：分离 Tab 的「最近分离」。本文只描述 v1 的落盘格式、失效语义和安全边界；
> 后端本身的接入说明仍在 `docs/vocal-separation-backend.md`。

## 1. 落点与格式

每次分离**成功**后，记录追加到：

```
<工程目录>/stems/history.json
```

不建立全局历史目录，也不把历史写到应用配置目录。工程内两轨音频仍由分离后端写在
`<工程目录>/stems/`；历史文件与它们同目录，复制/迁移一个工程目录即可连同历史一起带走。

当前 JSON schema：

```json
{
  "version": 1,
  "entries": [
    {
      "created_at_ms": 1789531200000,
      "input_path": "/Users/me/Music/song.flac",
      "vocals_file": "song_vocals.wav",
      "accompaniment_file": "song_accompaniment.wav",
      "duration_secs": 215.4,
      "sample_rate_hz": 48000
    }
  ]
}
```

- `created_at_ms`：Unix 毫秒时间戳，用于倒序显示；界面只展示最近 5 条。
- `input_path`：分离时的绝对输入路径，只作为历史元数据展示。历史回看/试听/导出不使用它读写文件。
- `vocals_file`、`accompaniment_file`：**裸文件名**。回看时用它们到当前工程的
  `stems/` 目录下解析，绝不直接使用索引里的整串路径。
- `duration_secs`、`sample_rate_hz`：能从两轨的标准 PCM WAV 头读取时写入；读不到时字段省略。

追加写使用 `aw_core::dub::write_atomic_explained`（同目录临时文件 + fsync + rename）。
若 `history.json` 损坏、版本不支持、路径不是普通文件或写入失败，分离 Tab 会如实显示失败原因；
已经写入的两轨结果仍作为“本次结果”可用，但不会被伪装成已写入历史。读到损坏索引时，
追加逻辑会先失败，不会把坏文件覆盖掉。

## 2. 路径安全

`history.json` 是可被用户手改的输入，不当作可信索引：

1. 两轨字段必须是单个裸文件名：非空、不是 `.`/`..`、不含 `/` 或 `\`、没有目录组件。
2. 解析时只允许在**当前工程的 `stems/` 目录内**定位；解析后还会做 canonicalize 前缀核对，
   防止父目录链接把文件带到工程外。
3. `stems/`、两轨本身都用 `symlink_metadata` 检查：拒绝软链、目录和其他非普通文件。
4. 不合法条目不删除、不自动修正，也不参与试听/导出；界面按“不可用”显示原因。

## 3. 失效语义

历史是“过去的结果”，不是当前稿件或当前工程状态的派生值：

- 改稿件、重新合成或重命名当前工程，不会修改已经落盘的历史条目。
- 历史记录的是绝对输入路径与两轨文件名。当前工程名改了，就会指向另一个工程目录；
  历史列表随当前工程目录切换，旧工程的历史不会跨工程合并显示。
- 两轨文件被用户手动删除或替换成软链后，条目仍保留，但界面显示“文件不在了/不可用”，
  试听与导出按钮禁用；点击条目会给出原因，不会静默无反应。
- 历史不自动清理。用户要清理时，手动删除 `stems/` 下对应音频，并删除
  `history.json` 中对应条目即可。v1 不提供历史删除、跨工程聚合或历史重命名。
