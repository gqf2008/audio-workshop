# 当前 11 → 9 元素版评审（v1.4 更新）

> 本文件是 v1 的**评审过程稿**，其中两条结论后来被推翻（见下表删除线/加粗处）：
> 抽屉最终是「全局设置」而不是「当前 Tab 的高级设置」；全局状态栏保留。
> 以 `screens.md` / `interaction-spec.md` / `information-architecture.md` 的现行版本为准。

> v1.4 吸收 ElevenLabs / Murf 的主流配音台模式：旁白块、Murf 式音色选择器、轨道结果、Voice Design 三件事和独立克隆向导。竞品依据见 `competitive-analysis.md`；逐 Tab 规则见 `interaction-spec.md`，可运行状态演示见 `interactive-prototype.html`。

## 1. 结论

当前版本解决了“配音首屏从 32 个组件降到 9~11 个组件”的密度问题，也保留了句子行“序号 + 文本 + 状态点”、选中后展开和右侧抽屉这几项正确方向。

但它仍然不是本轮目标的完整答案：

1. **只优化了配音 Tab 的密度，没有建立五 Tab 的产品信息架构。** 当前 `feat/ui-simplify` 顶部只有“配音 / BGM”两个 Tab；`feat/m4-song` 又引入“歌曲 / 素材库”，既不符合 v1.4 要求的五个入口，也把“素材库”误当成场景。
2. **把“参数少”误做成“所有低频能力塞进一个大抽屉”。** `WorkbenchDrawer` 同时包含工程、主题、音色、任务、导出，对任何 Tab 都不是一个清晰的高级面板。
3. **首屏低密度但状态模型不完整。** 空、运行、完成、失败、断点恢复没有形成一套一致的视觉规则；BGM 和音乐页仍是“标题 + 说明 + 多个按钮 + 进度 + 状态”的平铺。
4. **关键新场景缺失。** 人声分离在现有 UI 和仓库后端中都没有实现；音乐制作处于 M4 分支且仍叫“歌曲 · 彩蛋”，模型选择还在首屏；音色设计没有独立入口。
5. **音色设计现状必须讲清楚。** 单条 `voice_ref` 克隆已有基础，配音高级里的参考音频路径也已经存在；但 M4 P4 的多音色库、保存为音色、预设导入导出尚未完整实现，不能把它们写成现成能力。
6. **计数口径太容易规避。** “`grep` 到 9 条”不等于用户看到 9 个低密度元素；当前口径把标题栏、状态栏、抽屉开关也算进去，却没约束主操作数、可见参数数和失败恢复状态。

### 评审判定

- **保留方向：** 顶部 Tab 必须保留；句子行默认三元素必须保留；选中后展开必须保留；参数进入抽屉必须保留；浅色/深色统一主题必须保留。
- **必须删除：** 场景切换进抽屉、素材库 Tab、音乐首屏模型选择、BGM 三个并列主按钮、~~全局状态栏~~（**后改为保留**，见下表）和重复状态文本。
- **必须移动：** ~~进入当前 Tab 的高级抽屉~~（**后改为：各 Tab 独有参数进本页「高级」，全局项进「全局设置」卡片**）；全局工程/主题/服务/模型进全局设置。
- **必须回到首屏：** 配音“当前音色”是必需决策，必须是一等控件；不能只放在高级抽屉。
- **必须新增：** 顶部五 Tab（增加“音色设计”）、统一任务中心、人声分离工作台、音色设计工作台、按场景的能力未就绪态、任务失败/重试/恢复规则。

## 2. 对当前 9 个首屏元素的逐项处理

| 当前元素 | 处理 | 原因 |
|---|---|---|
| 标题栏（logo / 标题 / 窗口按钮） | 保留但简化 | 只保留应用与工程上下文；窗口按钮不计产品密度，不重复展示当前场景长标题 |
| 场景 Tab（当前仅配音 / BGM） | 保留并升级 | 改为始终可见的“配音 / BGM / 人声分离 / 音乐制作 / 音色设计”五 Tab；不放进抽屉 |
| 抽屉开关（三横条） | 保留但改名、改语义 | ~~从“工作台设置”变为“当前 Tab 的高级设置”；不再承载全局工程、主题和任务~~ **已被最终实现取代（见下）** |
| 稿件输入域 | 保留但状态化 | 编辑态用于稿件；运行/完成态折叠为摘要，避免 132px 大输入框一直占首屏 |
| 清空图标 | 删除独立首屏元素 | 改为输入域内的条件性 affordance 或右键/更多菜单；不再单独占元素预算 |
| 状态行（句数 / 已合成数） | 合并并保留一条 | 与当前阶段、失败、断点信息合并成一条“校听/任务状态行”；不并列第二个全局状态栏 |
| 开始合成 / 停止 / 停止试听 | 保留为一个主操作位 | 同一位置随状态变化，符合“每屏一个主任务”；不出现三个并列按钮 |
| 句子列表 | 保留 | 配音主画布的核心对象；默认行只显示序号、文本、状态点 |
| 全局状态栏（状态文本 / 引擎名） | ~~删除~~ **保留** | 这条评审结论**已被推翻**：实现保留全局状态栏并计入首屏 #8——它是五个 Tab 共用的唯一状态出口（服务连不上 / 任务失败要能全局看到），删掉后每个 Tab 都得自己复述一遍。 |

额外处理：

- 当前注释/文档存在漂移：源码头部仍写“场景导航并入抽屉”，实际已加回顶部 Tab；文档写 9 个元素，源码注释又写 11 个。新设计必须只保留一套口径。
- 默认装载示例稿会掩盖空态。空态、失败态、恢复态必须作为设计态单独验收，不能靠示例数据跳过。
- 句子行的选中展开是正确的渐进披露，但展开后应优先放“试听、重录、文本修正、错误详情”；seed、精确起始时间放任务详情或高级区。
- v1.4 新增“当前音色”控件后，首屏仍保持 ≤8：把项目名/保存状态/任务中心合并为项目条，把音色内部按钮合并为一个语义组。模型细节、参考音和语速留在高级抽屉。

## 3. 参数清理：保留、删除、移动

### 3.1 配音

| 参数 | 当前问题 | 新位置 |
|---|---|---|
| 当前音色 | 只存在于抽屉，用户打开配音后看不到声音决策 | 配音首屏 → 一等“当前音色”控件（名称/来源、试听、换音色、新建音色） |
| 模型细节 | 抽屉里与工程、主题混排 | 配音高级 → 模型细节组 |
| 语速 | 抽屉内可见，但和参考音、任务、导出堆在一起 | 配音高级 → 语音交付组 |
| 参考音路径 | 长文本输入，首屏不可见即可 | 配音高级 → 模型细节组；临时参考会更新当前音色的 clone 来源 |
| 数字 / 年份规范化 | 低频，不应成为主抽屉第一屏重点 | 配音高级 → 交付组 |
| 工程名 / 重新切句 | 与配音参数无关 | 项目条 / 项目设置 |
| 任务进度 / 试听全篇 | 不应和参数同一层 | 当前 Tab 状态行 + 任务中心 |
| 导出格式 / 输出目录 | 全部塞在同一个抽屉底部 | 统一导出抽屉；只在该结果有效时出现 |

### 3.2 BGM

当前 BGM 首屏有标题、说明、prompt、`生成并混音`、`试听混音`、`导出三轨`、进度条、状态文本，视觉上像一张设置表单，且存在 3 个并列按钮。新设计：

- 保留：prompt、`生成并混音`、一条状态、结果区。
- 删除：常驻标题和长说明、独立进度条叠状态文本、首屏 `试听混音` 和 `导出三轨` 两个并列按钮。
- 移动：时长、分段、duck gain、模型进 BGM 高级；导出格式和分轨选择进统一导出。
- 新增：结果态的“BGM / 混音”两轨结果区；无配音源时允许只生成 BGM，混音动作解释为何不可用。

### 3.3 音乐制作

`feat/m4-song` 的 `SongWorkbench` 目前首屏包含模型 segmented control、质量长说明、歌词、风格、生成、试听、导出、状态，超过目标密度。

- 保留：歌词、风格、生成主操作、试听/导出结果区。
- 删除：首屏模型选择、质量长文、首屏三个并列结果按钮。
- 移动：模型、步数、时长、语言、seed、许可说明进音乐高级；导出进统一导出。
- 重命名：从“歌曲 · 彩蛋”改为“音乐制作”，用轻量“实验性”标签表达风险，不用整段说明占据主画布。

### 3.4 人声分离

- 当前 UI 与后端都没有可复用的分离工作台。
- 新增：上传/拖入区、源文件摘要、主操作、阶段状态、两轨结果列表、下载动作。
- 高级区只显示后端真实存在的模型与阈值；后端未接入前显示能力未就绪，不制造假参数。

### 3.5 音色设计

当前没有独立入口，也没有完整音色库。新设计要分层表达现状：

- **已有基础：** 单条 `voice_ref` 克隆、参考音频输入、配音模型选择。
- **目标能力：** 音色设计试听、基础音色/参考音频选择、结果试听、保存为音色、导出/导入音色预设、在配音高级中复用。
- **必须能力门控：** 多音色库、音色持久化、预设格式、参考文本、风格/情绪和额外 seed 能力；没有真实后端支持时不能把滑杆或保存按钮伪装成已完成。

高级抽屉最多 3 组：基础音色/模型、参考音频与参考文本、风格/情绪/seed；没有真实后端能力时整组显示未就绪。

音色设计首屏只保留：

1. 顶部五 Tab；
2. 音色资产上下文条；
3. 主画布：默认试听文本 + 基础音色/参考音频；
4. 一个主操作：`生成试听`，完成后切为 `创建音色`；
5. 状态/恢复行；
6. 高级入口；
7. 任务中心入口；
8. 结果条：试听、保存为音色、预设菜单。

## 4. 当前抽屉的问题

`WorkbenchDrawer` 是一个“万能抽屉”，但用户打开它时并不知道自己在调当前任务、工程还是应用。

新结构应按上下文拆开：

```text
全局设置
├─ 主题
├─ 存储 / 导出目录
├─ 服务状态
└─ 关于 / 引擎信息

配音高级
├─ 音色
├─ 交付
└─ 导出

BGM 高级
├─ 生成
├─ 混音
└─ 导出

分离高级
├─ 模型
├─ 处理
└─ 输出

音乐高级
├─ 模型
├─ 生成
└─ 导出
```

抽屉仍然是一个，但内容随当前 Tab 变化，标题明确。任务中心是独立面板，不塞入高级抽屉。

## 5. 当前密度指标为什么不充分

当前文档以“`grep -c '// 首屏$'` = 9 ≤ 12”作为主要证明。这是有用的回归信号，但不能证明以下问题不存在：

- 9 个元素里可能包含 3 个并列主操作。
- 9 个元素可能同时包含空态、运行态和结果态的视觉焦点。
- 9 个元素可能在完成后仍然保留巨大的输入框。
- 9 个元素可能没有失败/重试/恢复入口。
- 9 个元素可能来自不同 Tab，却没有统一 Tab 导航。

Redesign v1.4 改为同时验收：

1. 首屏语义元素 ≤ 8（配音新增“当前音色”，通过合并项目/任务条保持预算）；
2. 每个稳定状态恰好 1 个主操作；
3. 首屏可见参数输入不超过场景预算；
4. 高级参数默认 0；
5. 首屏实现参数 0；
6. 空 / 运行 / 完成 / 失败 / 恢复五态各自可达；
7. 配音未选音色时主操作 disabled，完成后换音色产生 stale。

## 6. 保留清单

- 顶部一级导航的存在，但必须扩展为 5 个真实场景。
- 句子行默认三元素：序号、文本、状态点。
- 选中句子后再展开次级操作。
- 每屏一个视觉焦点。
- 使用右侧抽屉承载低频参数。
- 浅色 / 深色由统一主题控制。
- 配音工程的断点续作方向。
- 配音首屏“当前音色”一等控件与音色设计共享资产。

## 7. 删除清单

- 把场景导航藏入抽屉。
- “素材库”作为主 Tab；第五个主 Tab 应是“音色设计”。
- 万能 `工作台设置` 抽屉中的跨场景内容混排。
- 全局状态栏与场景内状态文本重复。
- 首屏模型选择器、seed、毫秒、时间轴刻度、完整引擎路径。
- 首屏并列的“生成 / 试听 / 导出”三按钮。
- 音乐页的整段质量说明和“歌曲 · 彩蛋”命名。
- 没有结果时仍然可见的导出主按钮。

## 8. 迁移优先级

1. 先统一五 Tab 和全局壳层，解决导航错误，并明确音色设计现状。
2. 再拆高级抽屉和任务中心，解决“参数多”和“切 Tab 丢状态”。
3. 再逐 Tab 做状态化主画布，优先配音和 BGM。
4. 接入音乐制作迁移和音色设计；音色设计先复用单条 voice_ref，P4 能力门控。
5. 最后接入人声分离能力门控。

## 9. v1.4 竞品模式吸收

- **Voiceover Studio → 旁白块**：当前音色不再是一条孤立参数行，而是彩色 dot + 音色名 + 来源 + 试听/换音色的旁白块头；稿件 / 句子直接挂在下方。采用它解决“声音决策和文本对象脱节”的问题。
- **Murf Studio → 音色发现**：选择器从简单下拉升级为搜索、真实可用筛选、音色卡片和试听；但默认收起，只保留当前音色行，避免五 Tab 首屏过载。
- **Studio 3.0 / Voiceover Studio → 轨道结果**：BGM、分离、音乐制品用轨道行呈现，高级参数不铺在结果区。采用其对象感，不照搬完整 timeline 编辑器。
- **Voice Design → 三件事**：音色设计首屏固定 Prompt + Text to preview + Generate voice；不把风格、seed、参考文本和专业克隆塞入主卡片。
- **Voice Cloning → 二级向导**：Instant / Professional Clone 采用 Add Voice → Voice Info → Finish up 分步结构，但不夸大当前单条 voice_ref 能力；专业克隆、样本持久化和音色库未完成时门控。

不采用：视频预览、多轨 DAW 编辑、完整音色市场常驻首屏、任何未实现的语言 / 性别 / 年龄 / Professional Clone 能力。
