# 音频作坊 · 产品设计说明 v0.1

> 依据：`CHARTER.md`（立项书）、`config/models.schema.yaml`（模型能力与 known_issues）、`tools/audio_dub.py` / `tools/audio_config.py`（M0 已有链路）。

## 1. 三场景功能清单与优先级

排序依据是 CHARTER 第 7 节的实测：只有 `audio8-tts 0.6B` 达到 **可懂度 98.5~100% / RTF 2~4 / 峰值 2.3~4.1G** 的可交付线；`audio8-tts-01b` 可懂度 0~3% 且时长乱跳（已是 `product_excluded`）；歌曲线 2'48" 的歌要 8 分钟且中文可懂度只有 85%（yue2）/ 71%（ace-step）。**所以界面资源按 8:2:0 分配——歌曲第一版不上界面。**

### 1.1 配音（主场景，全部资源优先）

|---|---|---|---|

## 2. 配音完整用户流程（每步含失败与重试）

主流程 7 步。**每一步的产物都要落盘**，任一环节崩掉都从该步续作，不重跑前面的步骤。

### 步骤 1 · 拿稿
- 入口：`导入 txt/md` / 粘贴 / 从剪贴板。md 自动去掉 `#` 标题行。
- 落盘：`project.json` 记 `script` 绝对路径 + `created`。
- 失败 ①**稿子为空或全是标题行**：不建工程，提示"没有可合成的句子"（已有实现）。
- 失败 ②**编码不是 UTF-8**（国内创作者常见 GB18030 稿）：按 UTF-8 → GB18030 → UTF-16 顺序探测，探测失败则弹"编码选择"下拉，不静默替换成乱码。
- 失败 ③**文件被占用/权限不足**：报路径 + 系统错误码，给"另存副本再导入"按钮。

### 步骤 2 · 切句
- 规则：`。！？；…` 断句；单句 > 80 字再按 `，、` 切（阈值来自配置，不写死）。
- 交互：切句结果以列表呈现，**允许手动合并/拆分/删除**（长句被切碎是配音最常见的返工点）。删掉的句子不参与合成，但保留在 `project.json` 里标记 `skipped`。
- 失败 ①**一句话超过 300 字仍无标点**（模型单请求上限 `max_chars_per_request: 300`）：按 `max_chars` 硬切并在该句标黄"可能读破"，提示补标点。
- 失败 ②**切出 0 句**：回步骤 1。
- 失败 ③**改稿后重新切句**：只影响 `pending` 的句子；已 `done` 的句子按文本哈希匹配，文本没变就不重合成（否则改一个字全篇重跑）。

### 步骤 3 · 文本兜底
- 顺序（与 `audio_config.normalize` 一致，配置驱动）：① 发音词典（user 级，最长匹配优先）→ ② 模型策略：`enforce` 做规则、`engine` 只做词典（上游已接 TN，避免双重转换）→ ③ 规则：年份逐位（2026 → 二零二六）、电话首位读幺、金额基数词、百分比、小数。
- 交互：**每句显示"原文本 → 实际读文"两行**，兜底过的句子标点。用户可直接编辑"实际读文"（等价于给这一句加一条一次性词典项）。
- 失败 ①**词典把常用词误替换**（如把"重庆"的"重"读法改坏）：词典条目按 `scope` 分层，用户级可单条停用；误替换立即回显，不需要重合成就能看出问题。
- 失败 ②**模型是 `engine` 策略但仍读错数字**（模型侧 TN 缺失）：在产品层提供"对本模型强制兜底"开关，覆盖配置的 `engine` 判定。
- 失败 ③**兜底后文本变长导致超限**：兜底后重新校验 `max_chars_per_request`，超限自动回到步骤 2 再切一句。

### 步骤 4 · 合成
- 行为：逐句 POST `/v1/tasks/run`（`model` + `text` + `seed` + `voice_ref`），拿到 base64 wav 落 `sentences/NNN.wav`，回填 `duration/sample_rate/channels/status`。
- 前置守卫（在发请求前做，不是出错后补救）：
  - `runtime.memory.min_free_memory_mb: 1024` —— 可用内存低于该值**不发请求**，先走卸载流程；
  - `max_loaded_models: 2` —— 配音场景常驻 1 个 TTS；跑评估台前先卸 TTS；
  - 服务不可达（`/v1/models` 探测超时）→ 提示"服务未启动" + 一键 `server ensure`，不把 90 句全标成失败。
- 进度：显示 `已完成/总数`、剩余句数预估耗时。**预估用实测 RTF 2~4**：5 分钟成品 ≈ 300s 音频 → 10~20 分钟纯合成，所以 M0 的 <10 分钟目标必须靠"边合成边校听"（见步骤 5）。
- 失败 ①**内存不足 / 503**（模型加载被内存守卫拒绝）：该句标 `error: oom` 并**保留在队列里**，不重试同一请求；提示"释放内存后继续"，给三个动作：卸载空闲模型 → 降到 q4_0 量化档（`precision_preference: [q8_0, q4_0]`）→ 关掉其它占内存的应用。用户点"继续"后**只重跑 error 的句子**。
- 失败 ②**单句超时**（默认 1800s，长句 + 机器忙时可能撞上）：按单句超时处理，标 `error: timeout`；**不自动重试同一句超过 2 次**（避免把机器钉死），第 3 次提示改用短文本或换模型。
- 失败 ③**返回体里没有 `audio` 字段**（服务内部错误）：把 `error` 原文截断到 200 字存进句子状态，附"复制详情"按钮，便于贴 issue；**不吞错**。
- 失败 ④**音色参考缺失**：`index-tts2` 硬要求 `voice_ref`，缺则直接 500 —— 在 UI 层强制先选音色（配置里已登记该 known_issue），不让用户撞到这个错。
- 失败 ⑤**句子合成出来时长异常**（对照文本字数估的期望时长偏离 > 2×）：不直接判失败，标黄"疑似异常"并在校听时排在前面 —— 这正是 0.1B 变体的失效特征（时长 0.37~9.89s 乱跳），0.6B 偶发时也要能被发现。
- 失败 ⑥**服务进程被杀/机器休眠**：正在合成的句子保持 `pending`（不是 error），下次进入工程提示"有 N 句未完成，继续合成？"。

### 步骤 5 · 校听
- 行为：逐句播放 + 波形/时长，空格播放/暂停、上下键翻句、`R` 重录当前句。**支持 1.25×/1.5× 倍速**——校听是 5 分钟稿里最耗时的人工环节，倍速直接决定能不能压进 10 分钟。
- 重点排序：把 `error` / "疑似异常" / 兜底过的句子排在列表最前面，先听最可能出问题的。
- 失败 ①**听不出对错**（数字/专名读法）：一键"只播这句的 3 个 seed 变体"做 AB 对比（同文本不同 seed，复用 §2 步骤 4 的合成接口）。
- 失败 ②**播放设备切换/独占导致没声音**：切设备后重试一次；仍无声则提示检查系统输出设备，**不阻塞校听流程**（可先标"待听"继续往后走）。
- 失败 ③**校听到一半发现稿子要改**：回步骤 1/2，改动只影响文本变了的句子（同步骤 2 的文本哈希匹配）。

### 步骤 6 · 单句重录
- 行为：可只重录、可改文本后重录。重录时 `seed += 1000`（避免复现同一条不满意的音频，已有实现），合成完**自动重拼装 + 重算该句之后的时间轴**（不需要用户手动 assemble）。
- 失败 ①**重录后仍不满意**：连点重录每次换 seed；给"锁 seed 复现"按钮，把当前 seed 记进工程（可复现是付费点 ②，见 §4）。
- 失败 ②**改文本后与前后句衔接突兀**：提示句间停顿 `gap_ms` 可调，并在导出前提供"整段试听"。
- 失败 ③**采样率/声道与其它句不一致**（切了模型或改了量化档）：拼装前校验，不一致直接拒绝拼装并指出是哪一句（已有实现）——不允许产出静默损坏的成品。

### 步骤 7 · 导出
- 产物：`out/final.wav`（单声道/双声道按源，16-bit）+ `out/final.srt`（句子级时间轴）。
- 付费点：无损 wav 导出在 M0 免费；**批量导出 / 分轨导出 / 自动压成 mp3 属于付费**（§4）。
- 失败 ①**磁盘空间不足**：写前检查目标卷剩余空间（成品大小 ≈ 采样率 × 2B × 时长），不足则报"需要 X MB"。
- 失败 ②**目标文件被占用**（Windows/剪映正打开着）：写到临时文件再原子替换，失败则报占用进程提示。
- 失败 ③**文件名非法/过长**：以工程目录名生成，非法字符替换，超长截断并保证唯一。

## 3. 信息架构

只有一个主界面，其余都是从属面板——创作者打开软件就是要配音，不该先选场景。

```
┌ 顶栏：场景切换 [配音][BGM][歌曲(灰)]   ·   服务状态灯   ·   设置
│
├ 配音工作台（默认主界面，三栏）
│   ├ 左栏 句子列表（虚拟滚动）
│   │    每行：#序号 · 状态(✅/待/❌/⚠️) · 读文前 40 字 · 时长
│   │    顶部筛选：[全部][异常][已兜底][未合成]
│   ├ 中栏 当前句详情（单实例，按选中句重建）
│   │    原文本 / 实际读文（可编辑）· 句级 seed · 重录 · 试听
│   │    兜底说明（哪条规则/哪条词典命中）
│   └ 右栏 整篇控制
│        稿子路径 · 句数/总时长 · 语速 rate · 停顿 gap_ms · 音色
│        [开始合成] [继续合成(仅异常句)] [整段试听] [导出]
│
├ 从属面板（抽屉/弹窗，不占主界面）
│   ├ 音色管理：内置音色列表 · 克隆音色（本地参考音频 + ref_text + 试听）
│   ├ 模型管理：已装模型 · 量化档 · known_issues 只读展示 · 下载器
│   ├ 发音词典：词条 CRUD · scope(user/profile/model) · 作用域预览
│   └ 设置：后端(Metal/CUDA) · 线程 · 模型目录 · 内存策略 · 导出格式
│
└ 底栏：进度条（第 N/共 M 句）· 当前耗时 · 剩余预估 · 取消
```

导航原则：
1. **场景是顶栏第一级，模型不是**——`product_excluded` 的模型（audio8-tts-01b 及其 stream 变体）在模型管理里也**不可选**，只在"为什么没有它"的说明里出现。
2. **异常必须可见**：任何 `error`/`⚠️` 都要在左栏列表里 greppable，导出按钮在存在未完成句子时**禁用并说明原因**（不允许导出一半）。
3. `known_issues` 在模型选择处只读展示——让产品"知道自己站在什么上"，用户也能解释"为什么这模型读数字不稳"。
4. 歌曲入口第一版灰置，hover 提示"质量未达产品级，暂不开放"。

## 4. 付费点：开源/付费边界落到具体功能条目

CHARTER 第 5 节的边界在这里变成可被 UI 直接引用的条目。"开源"的那部分**免费且必须能用**——否则等于自断回馈上游的路。

### 4.1 免费（开源层，对应仓库 `tools/`）

| 能力 | 具体形态 | 级别 |
|---|---|---|
| 配音主链路 | 步骤 1~7 全部：拿稿/切句/兜底/合成/校听/单句重录/导出 wav+srt | **[M0]** |
| 文本兜底层 | 数字规范化 + 发音词典 | **[M0]** |

### 4.3 许可红线（硬约束，不是可选项）

- **只做下载器，不打包权重**：P9 下载器必须让用户从上游源拉取，发行版内**不含任何权重文件**。
- 配置层区分"可商用 / 仅自用"：非商用（CC-BY-NC）模型在 UI 上明确标注，并在导出时提示"该音色/模型仅限自用"。
- 免费侧不能是残废版：M0 的三条成功标准（连续 7 天、不退回剪映、5 分钟稿 <10 分钟）**必须靠免费层达成**，否则没有用户验证（CHARTER 第 10 节）可做。

## 5. 技术栈约定

### 5.1 前端：Rust + Slint 1.17 + slint-pixel 0.2.1

- **只用 `Pixel*` 控件**，不混用原生 Fluent 控件（像素风混原生控件会立刻破功）。从 `@slint_pixel` 统一导入（`ui/lib.slint` 汇总入口）。
- 各栏控件选型（均已存在于 slint-pixel 0.2.1）：

| 位置 | 控件 |
|---|---|
| 句子列表（左栏） | `PixelVirtualList` / `PixelList` + `PixelSearchBox`（筛选用 `PixelSegmentedControl`） |
| 当前句详情（中栏） | `PixelTextArea`（读文可编辑）+ `PixelAudioPlayer` + `PixelButton`（重录/试听） |
| 整篇控制（右栏） | `PixelSlider`（语速）+ `PixelNumberInput`（停顿 ms）+ `PixelSelect`（音色） |
| 进度/状态 | `PixelProgressBar` + `PixelSteps` + `PixelAlert`（错误横幅） |
| 从属面板 | `PixelDrawer` / `PixelDialog` + `PixelTabs` + `PixelDataTable`（模型管理） |
| 工程历史 | `PixelTimeline`（P5） |

- **三条必须遵守的组件约束**（都是踩过的坑，直接影响可用性）：
  1. **每个 `PixelButton` 必须写显式 `width`**：`PixelButton` 内部子元素全是 `width:100%`，Slint 里百分比子元素不贡献 preferred-width，组件自身 preferred-width = 0，放进 `HorizontalBox` 后宽度为 0 —— 不渲染、点不到（表现为"按钮不能点击"）。优先用组件库已修的 `preferred-width` 版本，同时保留显式 width 兜底。
  2. **中栏详情是单实例组件**：Slint 交互组件（复选框/输入框/下拉）一旦被赋值就永久移除声明处绑定，切选中句时会残留上一句的值。**用单元素 model + `for` 渲染让选中句切换时销毁重建**；或退回双向绑定 `<=>`（`TwoWayBinding::intercept_set` 不摘绑定）。Rust 侧 `set_selected` 不会触发 Slint 的选中回调，装载/切句/写回/增删句/外部改盘重载每条路径都必须走同一个刷新入口。
  3. **`for` 不能直接占 `GridBox` 单元格**：会报 `grid_layout_input_data() not implemented`（运行时崩，非编译错）。所有 `for` 必须包进独占的 `HorizontalBox`/`VerticalBox`，且跨列要显式 `colspan`。
- **Rust 侧职责**：工程状态机（句子状态/seed/时间轴）、服务调用（HTTP + base64）、文件落盘、音频拼接。**大函数/Slint 映射逻辑放 Rust**，避免 slint-build 在 Windows 下栈溢出。
- 线程与 UI：合成在后台线程，UI 更新必须走 `upgrade_in_event_loop`（`Weak::upgrade` 仅创建线程可用）；`invoke_from_event_loop` 的闭包要求 `Send`，不要往里塞 `Rc`。

### 5.2 与现有 Python 工具的关系与边界

| 组件 | 角色 | 与产品界面的边界 |
|---|---|---|
| `config/models.schema.yaml` | **唯一事实源**：场景定义、模型旋钮、`known_issues`、`product_excluded`、文本规则 | 界面**不复制**这些决策，只读并渲染；模型管理面板显示的就是它的内容 |
| `tools/audio_config.py` | 配置层引用实现：渲染 `server.json`、文本兜底（规范化 + 词典）、按场景执行 | **文本层的算法必须以此为准**（`normalize()` / `verbalize()` / `apply_dictionary()`）；Rust 侧要么调它、要么逐条对齐并写等价测试，不允许两份实现各写各的 |
| `tools/audio_dub.py` | 配音链路参考实现：切句、逐句合成、拼装、单句重录、`project.json` 结构 | **Rust 状态机的行为基线**：`project.json` 的字段（`sentences[].text/spoken/seed/wav/duration/start/status`）直接沿用，保证 CLI 与界面能开同一个工程 |
| `tools/audio_eval.py` | 评估台：可懂度/耗时/峰值内存 + 回归对比 | 产品**不重复实现评估**；界面上"质量自检"按钮就是调它；每次换配置/换量化档后跑一遍 |
| `audio.cpp`（submodule，锁 tag） | 引擎与服务（`audiocpp_server`，`127.0.0.1:8080`） | 适配只写在本仓库薄层，滞后上游 1~2 版；上游接口变了改我们这层 |
| 上游文本规范化 | 模型侧 TN（`engine` 策略） | 模型已接 TN 的（如 index-tts2）**不重复处理**，避免双重转换 —— 这由配置的 `text_overrides.normalization` 决定，不写死在代码里 |

**总边界一句话**：Python 工具 = 开源层（可被任何人脚本化、可被评估、可被替换）；Rust 桌面 App = 产品本体（把配置层与链路的决策变成按钮，并承担付费能力）。两者共享同一份配置与同一个 `project.json`，**不共享状态**。

### 5.3 性能与资源预算（来自 CHARTER 第 7 节实测）

- 配音合成按 **RTF 2~4** 估：5 分钟成品（300s 音频）纯合成 **10~20 分钟**，所以"5 分钟稿 <10 分钟出片"**必须靠边合成边校听**（步骤 4/5 流水线），不能等全部合成完再校听。
- 峰值内存 **2.3~4.1G**：`max_loaded_models: 2` 是创作者机器的保守值；跑评估台（需要额外 ASR 模型）前先卸 TTS。
- 歌曲线 2'48" 需 8 分钟（yue2）/ 120s 需 6.4 分钟（ace-step）——这是它降级为彩蛋的直接原因。
- 界面不阻塞：合成的 HTTP 超时是 1800s（长句 + 慢机器），UI 必须全程可交互、可取消。
