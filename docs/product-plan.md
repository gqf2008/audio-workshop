## 2. 配音完整用户流程（每步含失败与重试）

主流程 7 步。**每一步的产物都要落盘**，任一环节崩掉都从该步续作，不重跑前面的步骤。

**落盘不变式（评审补齐；已在 `fix/text-layer-and-dataloss` 实现，随本轮合并进入 main）**：所有产物一律"**临时文件 + fsync + 原子替换**"（`tools/audio_dub.py::write_atomic`，用于 `project.json` / `sentences/NNN.wav` / `out/final.srt`）；`final.wav` 走的是同一套模式但不是同一个调用——`cmd_assemble` 自建 `final.wav.tmp<pid>`，写完 `flush` + `fsync` 再 `os.replace`（该 fsync 由 `fix/eval-tn-convergence` 补上）。拼装前逐句校验，**截断按实际字节数判定**（头里声明的帧数不会随尾部截断改变，唯一可信判据是 `实际字节数 ≥ 44 + 帧数 × 声道 × 位深字节`，`cmd_assemble`）。

### 步骤 1 · 拿稿
- 入口：`导入 txt/md`（**M0**）/ 粘贴（**[M1]**，D1b）。md 自动去掉 `#` 标题行。
- 落盘：`project.json` 记 `script` 绝对路径 + `created`。
- 失败 ①**稿子为空或全是标题行**：不建工程，提示"没有可合成的句子"（已有实现）。
- 失败 ②**编码不是 UTF-8**（国内创作者常见 GB18030 稿）：按 UTF-8 → GB18030 → UTF-16 顺序探测，探测失败则弹"编码选择"下拉，不静默替换成乱码。
- 失败 ③**文件被占用/权限不足**：报路径 + 系统错误码，给"另存副本再导入"按钮。

### 步骤 2 · 切句
- 规则：`。！？；…` 断句；单句 > 80 字再按 `，、` 切（阈值来自配置，不写死）。
- 交互（**M0 只做"整篇重切"**）：重切 = 按新稿重建句子表；已 `done` 的句子**不复用**，靠句级 seed（`base_seed + index`）让新一轮能复现上一轮听过的句子。手动合并/拆分/删除句（D2b）与"改稿重切 + 哈希复用"（失败 ③）整体降 **[M1]**。
- **M0 不引入 `skipped` 状态**（评审指出，当前数据模型里它不存在）：句子身份就是 `index`，没有稳定 `id`、没有文本哈希字段；更关键的是 `cmd_synth` 的待合成集合是"`status != "done"`"（`tools/audio_dub.py::cmd_synth`），**任何新状态（含 `skipped`）都会被当成待合成**。要让"删掉的句子不参与合成 / 改稿只重跑变化的句子"成立，必须先给 `project.json` 加稳定 `id`（与哈希字段）并同步改这个筛选条件 —— 与 D15 一起放到 M1。
- 失败 ①**一句话超过 300 字仍无标点**（模型单请求上限 `max_chars_per_request: 300`）：按 `max_chars` 硬切并在该句标黄"可能读破"，提示补标点。
- 失败 ②**切出 0 句**：回步骤 1。
- 失败 ③**改稿后重新切句**（**[M1]**，D15）：只影响 `pending` 的句子；已 `done` 的句子按文本哈希匹配，文本没变就不重合成（否则改一个字全篇重跑）。**这不是 M0 的门槛**——M0 的退路是整篇重切 + 同 seed 复现。

### 步骤 3 · 文本兜底
- 顺序（与 `audio_config.normalize` 一致，配置驱动）：① 发音词典（user 级，最长匹配优先）→ ② 模型策略：`enforce` 做规则、`engine` 只做词典（上游已接 TN，避免双重转换）→ ③ 规则：年份逐位（2026 → 二零二六）、电话首位读幺、金额基数词、百分比、小数。
- 匹配方式（评审补）：规则用"**左右不挨着数字**"的前后瞻（`(?<!\d)` / `(?!\d)`），**不是 `\b` 词边界** —— Python 里汉字属于 `\w`，"今年2026年"这种**数字紧贴汉字**的写法会让 `\b` 版本整条规则静默失效（M0 之前就是这样，修复见 `tools/audio_config.py::verbalize`）。
- 交互：**每句显示"原文本 → 实际读文"两行**（M0 在列表里输出，M1 做界面），兜底过的句子标点。用户可直接编辑"实际读文"（等价于给这一句加一条一次性词典项；界面编辑属 M1）。
- 失败 ①**词典把常用词误替换**（如把"重庆"的"重"读法改坏）：词典条目按 `scope` 分层，用户级可单条停用；误替换立即回显，不需要重合成就能看出问题。
- 失败 ②**模型是 `engine` 策略但仍读错数字**（模型侧 TN 缺失）：在产品层提供"对本模型强制兜底"开关，覆盖配置的 `engine` 判定。
- 失败 ③**兜底后文本变长导致超限**：兜底后重新校验 `max_chars_per_request`，超限自动回到步骤 2 再切一句。

### 步骤 4 · 合成
- 行为：逐句 POST `/v1/tasks/run`（`model` + `text` + `seed` + `voice_ref`），拿到 base64 wav 落 `sentences/NNN.wav`，回填 `duration/sample_rate/channels/status`。
- 前置守卫（在发请求前做，不是出错后补救）：
  - `runtime.memory.min_free_memory_mb: 1024` —— 可用内存低于该值**不发请求**，先走卸载流程；
  - `max_loaded_models: 2` —— 配音场景常驻 1 个 TTS；跑评估台前先卸 TTS；
  - 服务不可达（`/v1/models` 探测超时）→ 提示"服务未启动" + 一键 `server ensure`，不把 90 句全标成失败。
- 进度与**两个必须分开说的数字**（评审修正 v0.1 的算术错误）：
  - **挂钟时间**：5 分钟成品 ≈ 300s 音频 × RTF 2~4 = **10~20 分钟纯合成**，且 RTF 2~4 是**单句短文本**实测（CHARTER §7），90 句串行产线还要叠加模型加载、内存守卫、逐句落盘 → wall clock **只会更长**；**重叠不缩短关键路径**。
  - **人工投入**：校听 + 重录 + 导出的人工时间，靠"边合成边校听"压缩。
  - 所以 M0 的标准写成**条件式**：**"人工投入 <10 分钟 / 出片 ≤ 纯合成时间 ×1.2"**（CHARTER §2 第 3 条同步）——RTF 2 端 ≈12 分钟、RTF 4 端 ≈24 分钟，**"出片 ≤20 分钟"在 RTF≈4 端不可达**（纯合成就 ≈20 分钟，再叠加 90 句串行产线的加载/内存守卫/逐句落盘只会更长），必须等 M0 端到端把 RTF 实测出来再定标。它**不是** v0.1 写的"出片 <10 分钟"（算术上不可达），也**不是一个与 RTF 无关的硬阈值**。
  - **M0 的第一件事**：拿一篇真实的 5 分钟稿量跑一次端到端（`cmd_run`），把挂钟时间与人工投入量出来，再谈优化；在量出来之前不承诺任何耗时数字。
  - **边合成边校听的现成增量机制（v0.1 漏掉）**：`audio8-tts-stream`（**0.6B，未 `product_excluded`**，`mode: streaming`，走 `/v1/audio/speech/live`，见 `config/models.schema.yaml`）可以首句先出音频、后续句子陆续到达，是"边合成边校听"的真机制（配置已标注"离线批量与评估不适用"——所以只用作校听增量通道，不替代 `/v1/tasks/run`）。
- 失败 ①**内存不足 / 503**（模型加载被内存守卫拒绝）：该句标 `error: oom` 并**保留在队列里**，不重试同一请求；提示"释放内存后继续"，给三个动作：释放模型内存（服务端只有全局 `POST /v1/tasks/unload_all_models`，确认后会卸载所有已加载模型）→ 降到 q4_0 量化档（`precision_preference: [q8_0, q4_0]`）→ 关掉其它占内存的应用。用户点"继续"后**只重跑 error 的句子**。
- 失败 ②**单句超时**（默认 1800s，长句 + 机器忙时可能撞上）：按单句超时处理，标 `error: timeout`；**不自动重试同一句超过 2 次**（避免把机器钉死），第 3 次提示改用短文本或换模型。
- 失败 ③**返回体里没有 `audio` 字段**（服务内部错误）：把 `error` 原文截断到 200 字存进句子状态，附"复制详情"按钮，便于贴 issue；**不吞错**。
- 失败 ④**音色参考缺失**：`index-tts2` 硬要求 `voice_ref`，缺则直接 500 —— 在 UI 层强制先选音色（配置里已登记该 known_issue），不让用户撞到这个错。
- 失败 ⑤**句子合成出来时长异常**（对照文本字数估的期望时长偏离 > 2×）：不直接判失败，标黄"疑似异常"并在校听时排在前面 —— 这正是 0.1B 变体的失效特征（时长 0.37~9.89s 乱跳），0.6B 偶发时也要能被发现。
- 失败 ⑥**服务进程被杀/机器休眠**：正在合成的句子保持 `pending`（不是 error）；下次进入工程提示"有 N 句未完成，继续合成？"（`cmd_synth` 重跑时天然跳过 `done`、重试 `error`）。
- 失败 ⑦**落盘时磁盘满**（数据丢失路径；**如实描述，评审要求**）：写 `sentences/NNN.wav` 走 `write_atomic`（临时文件 + `fsync` + `os.replace`，`fix/text-layer-and-dataloss` 实现）→ **磁盘满发生在临时文件阶段**：原文件不被破坏、不会留下半个 wav 冒充成品。**已实现（`feat/cli-disk-boundary`，`tools/audio_dub.py::cmd_synth` + `write_failure_note`/`is_enospc`）**：捕获 `errno.ENOSPC` 后把该句标成 `error: ENOSPC（需要 X MB）`（字节数取本次实际要写的 `len(raw)`，不估）、把工程落盘、然后**本轮收尾**（不再继续合成——继续只会每句都失败），退出码 1，**不再冒泡裸 traceback**；释放空间后重跑 `audio-dub synth <dir>` 只会处理 `status != done` 的句子（error 句天然在其中）。
- 失败 ⑧**写盘完整性**（尾部截断 / 文件系统异常；**如实描述**）：完整性由 `write_atomic` 保证——"写满 `len(raw)` 字节 + `fsync` 之后才 rename，失败即抛异常"，因此**不会出现"状态 `done` 但文件是残的"**。v0.2 写的"`cmd_synth` 写完回读 `os.path.getsize(path) != len(raw)`"**在 `fix/eval-tn-convergence` 中已删除**（恒为假、属装饰性守卫）；截断检测改由 `cmd_assemble` 在拼装前按实际字节数拦截（见步骤 6 失败③，`fix/text-layer-and-dataloss`）。

### 步骤 5 · 校听
- 行为（**M0 = 最小形态**）：顺序播放 + 逐句跳转（命令行），把 `error` / "疑似异常" / 兜底过的句子排在前面先听。
- **[M1]** 校听器：波形/时长、1.25×/1.5× 倍速、键盘翻句（D6b）——倍速直接决定人工校听时长，但实现依赖 Slint 壳（CHARTER §9）。
- 失败 ①**听不出对错**（数字/专名读法）：一键"只播这句的 3 个 seed 变体"做 AB 对比（同文本不同 seed，复用步骤 4 的合成接口）。
- 失败 ②**播放设备切换/独占导致没声音**：切设备后重试一次；仍无声则提示检查系统输出设备，**不阻塞校听流程**（可先标"待听"继续往后走）。
- 失败 ③**校听到一半发现稿子要改**：**[M1]** 回步骤 1/2，改动只影响文本变了的句子（同步骤 2 失败 ③ 的哈希匹配，依赖稳定 `id`）。

### 步骤 6 · 单句重录
- 行为：可只重录、可改文本后重录。重录时 `seed += 1000`（避免复现同一条不满意的音频，已有实现），合成完**自动重拼装 + 重算该句之后的时间轴**（不需要用户手动 assemble）。
- 失败 ①**重录后仍不满意**：连点重录每次换 seed；"锁 seed 复现"把当前 seed 记进工程 —— **这是免费能力**（§4.1），不是付费点。
- 失败 ②**改文本后与前后句衔接突兀**：提示句间停顿 `gap_ms` 可调，并在导出前提供"整段试听"。
- 失败 ③**位深/采样率/声道与其它句不一致**（切了模型或改了量化档）：**已在 `fix/text-layer-and-dataloss` 实现，随本轮合并进入 main**——拼装前逐句校验——**位深必须是 16-bit（`sampwidth == 2`）**、采样率与声道必须与该句元数据一致；任何一句不符即**拒绝拼装**并指出是哪一句；全篇内部采样率/声道不一致也整体中止（`cmd_assemble`）。不允许产出静默损坏的成品。
- 失败 ④**句子 wav 丢失但状态仍是 `done`**（手动删了文件 / 同步工具搬走 / 外置卷未挂载）：**`fix/text-layer-and-dataloss` 已实现**（随本轮合并进入 main）——拼装前按句校验文件存在性（`os.path.isfile`），缺失即中止并列出句号——**不允许"跳过缺失句继续拼"**（那会产出与 srt 时间轴静默错位的成品）。

### 步骤 7 · 导出
- 产物：`out/final.wav`（单声道/双声道按源，16-bit）+ `out/final.srt`（句子级时间轴）。
- 付费点：无损 wav 导出在 M0 免费；**批量导出 / 分轨导出属于付费（P6）**（§4.2）。
- 失败 ①**磁盘空间不足**：拼装走"临时文件 + 原子替换"（`cmd_assemble`，`fix/text-layer-and-dataloss` 实现），磁盘满时**旧成品保持可用**（这条成立），**已实现写前检查**（`feat/cli-disk-boundary`，`tools/audio_dub.py::cmd_assemble`）：拼装前按「Σ逐句 wav 字节 + 句间静音」估算需要量（句数按工程全量句数算，是上界），与 `shutil.disk_usage` 的可用量比较，不足即报「需要 X MB / 可用 Y MB」并中止，**不创建临时文件**；若写的过程中仍然 ENOSPC（检查与实际之间有竞态），清理临时文件并给出同一口径的可执行文案，旧成品不受影响。
- 失败 ②**目标文件被占用**（Windows/剪映正打开着）：写到临时文件再原子替换（`os.replace`），失败则报占用进程提示。
- 失败 ③**文件名非法/过长**：以工程目录名生成，非法字符替换，超长截断并保证唯一。
- 失败 ④**工程文件损坏**（`project.json` 被截断 / JSON 不可解析，例如旧版非原子写留下半截文件）：`load_project` 直接 `json.load` —— **不猜测、不半读、不自动修复**，解析失败即抛 `JSONDecodeError` 回溯退出。**"读取即报'工程文件损坏'并给出路径"这句友好提示尚未实现**（v0.2 描述与代码不符），**列为待补**。`project.json` 现在也是原子写（`fix/text-layer-and-dataloss`，随本轮合并进入 main）；同目录若残留 `project.json.tmp<pid>` 属可辨识残留，人工确认后处理。M0 的恢复路径是**重建工程**（稿子 + `base_seed` 决定内容），代价可接受。

### 3.2 目标信息架构（原型 → 收敛后的形态）

只有一个主界面，其余都是从属面板——创作者打开软件就是要配音，**不做"先选场景"的启动页**（场景是顶栏上的一个切换器，默认停"配音"），也不该一次看到全部功能。

```
┌ 顶栏：场景 [配音][BGM(灰)][歌曲(灰)] · 工程名 · 服务状态灯（含设置入口）   ← 3 个并列元素（R7）
│      BGM 属 M2、歌曲属 M4：未到阶段的场景一律灰置（hover 说明"未开放"）；默认停"配音"，不做启动选场景页
├ 主屏（一屏一事）：
│   ① 稿件：多行输入 + 字数/预计时长 + [载入示例稿] [重新切句]（限宽居中）  ← D1/D1b 的导入落点
│   ② 句子列表（虚拟滚动），列表头一行：筛选 [全部][异常][已兜底][未合成] + 计数
│      每行：序号 · 文本（单行省略）· 状态点            ← R3，行高 48px（选中展开 92px），间距 ≥16px
│      选中行展开（一个展开区，同级 ≤3）：时长 · 起始 · 状态 + [试听] [重录]   ← R4
│                                        + 原文本 / 实际读文（可编辑）· 句级 seed（M1 补）
│
├ 抽屉（默认收起，一次只开一个）：音色（含语速/停顿） · 导出 · 进度与任务（[开始合成]） · 发音词典 · 模型管理
│       ↑ 进度条/剩余预估、音色选择、语速与句间停顿、导出选项、词典、模型管理都在这里（R2：一屏一事）
│
└ 底栏：时间轴细条（≈43px，无播放器控件；只标位置，播放属于校听器）    ← R5
```

**归属与落点（评审要求逐条闭合）**：

- **稿件导入落在主屏第①块**（D1 文件导入 / D1b 粘贴共用同一输入区）：`重新切句` 就地重切。§1.1 里 D1b 的 `[M1]` 指"剪贴板按钮 / 拖拽"这类 GUI 形态，不是输入框本身。
- **语速（`rate`）与句间停顿（`gap_ms`）都归「音色」抽屉**：原型把语速滑杆放在音色段（停顿滑杆 M1 与语速同段补上）；与 D10 的 `[M1]`、CHARTER §9 的 M1 一致。
- **`PixelSearchBox` 不进第一版**：§5.1 原文列了它，但 §3.2 没有搜索落点（虚拟滚动 + 筛选够用）；要加必须先补 IA 并占 R1 预算（§5.1 同步）。
- **`[开始合成]` 在「进度与任务」抽屉里**（原型如此，也是 R2"进度/任务进抽屉"的必然结果），首屏不常驻主按钮；导出按钮在存在未完成句子时**禁用并说明原因**（§3.3 第 2 条）。
- **筛选条是 M1 目标**：原型列表头只有「句子 + 计数」，第一版靠状态点 + `error`/疑似异常排前（§2 步骤 5）保证异常可见。
- **工程名**：原型放在「工程」抽屉；§3.1 预算按顶栏计入 1 个组件，两种放法都在 R1 上限内（M1 定稿时二选一）。
- **`[BGM]` 灰置到 M2、`[歌曲]` 灰置到 M4**（CHARTER §9；§3.3 第 4 条）。

### 3.3 导航原则

1. **场景是顶栏第一级，模型不是**——`product_excluded` 的模型（audio8-tts-01b 及其 stream 变体）在模型管理里也**不可选**，只在"为什么没有它"的说明里出现。
2. **异常必须可见**：任何 `error`/`⚠️` 都要在句列表里 greppable，导出按钮在存在未完成句子时**禁用并说明原因**（不允许导出一半）。
3. `known_issues` 在模型选择处只读展示——让产品"知道自己站在什么上"，用户也能解释"为什么这模型读数字不稳"。
4. 歌曲入口第一版灰置，hover 提示"质量未达产品级，暂不开放"；**BGM 入口同样灰置到 M2**（CHARTER §9：M2 = BGM 接入），hover 说明"BGM 未开放"。
5. **R1~R8 是评审红线，不是风格偏好**：新增任何常驻控件都要先回答"它能进抽屉吗"；密度回退按 §3.1 表格逐条打回。

## 5. 技术栈约定

### 5.1 前端：Rust + Slint 1.17 + slint-pixel 0.2.1

- **只用 `Pixel*` 控件**（约定，非红线）：不混用原生 Fluent 控件（像素风混原生控件会立刻破功）。统一从 `@slint_pixel` 导入；**这个别名指向组件库内部的汇总入口 `ui/lib.slint`（`slint-pixel-0.2.1/ui/`），不是本仓库的文件**——本仓库的 `ui/` 只有 `app.slint` / `dub_workbench.slint` / `model.slint`，别名由 `build.rs` 的 `slint_pixel::library_paths()` 注册。
- 控件选型（**[M1]** 校听器与工作台相关：`PixelAudioPlayer` / `PixelTimeline` 属 M1，M0 不引入界面依赖）：

| 位置 | 控件 |
|---|---|
| 句子列表（主屏） | `PixelVirtualList` / `PixelList` + `PixelSegmentedControl`（筛选）。**`PixelSearchBox` 去留（评审要求闭合）**：§3.2 没有搜索落点，第一版**不做**——要加必须先补 IA 并占 R1 预算 |
| 选中行展开 | `PixelTextArea`（读文可编辑）+ `PixelButton`（重录/试听） |
| 抽屉（音色/导出/进度/词典/模型） | `PixelDrawer` / `PixelDialog` + `PixelTabs` + `PixelDataTable`（模型管理） |
| 整篇控制（都在「音色」抽屉，§3.2） | `PixelSlider`（语速）+ `PixelNumberInput`（停顿 ms，M1 补）+ `PixelSelect`（音色） |
| 进度/状态（抽屉内，R2） | `PixelProgressBar` + `PixelAlert`（错误横幅） |
| 时间轴（底部细条，R5） | `PixelTimeline`（≤48px，不带播放器控件） |
| 校听器（M1） | `PixelAudioPlayer`（波形/倍速/键盘翻句） |

- **三条组件注意点**（评审降级：由 v0.1 的"必须遵守"改为"注意点 + 触发条件 + 已验证版本"）：
  1. **`PixelButton` 的自然宽 → 触发条件：组件库版本。** `PixelButton` 内部子元素全是 `width: 100%`，百分比子元素不贡献 preferred-width；**老版本（< 0.2.1）组件自身 `preferred-width = 0`**，放进 `HorizontalBox` 后宽度塌缩成 0 → 不渲染、点不到。**已验证版本：pin 住的 `slint-pixel 0.2.1` 已修**（组件库内 `slint-pixel-0.2.1/ui/pixel_painter_widget.slint:213`：`preferred-width: btn-text.preferred-width + 20px`），所以正常使用**不必**再写显式 `width`；只有自建按钮、或将来把组件库降级回旧版时才需要显式 `width` 兜底。
  2. **选中句详情是单实例组件 → 触发条件：用 Slint 交互组件承接"选中项"。** 交互组件（复选框/输入框/下拉）一旦被赋值就永久移除声明处的绑定，切选中句时会残留上一句的值（属实）。**两种可行做法二选一即可**：单元素 model + `for` 渲染（切句销毁重建），或双向绑定 `<=>`（`TwoWayBinding::intercept_set` 不摘绑定）——不该写成"必须用哪一种"。真正硬的一条是另一件事：Rust 侧 `set_selected` **不会**触发 Slint 的选中回调，所以装载 / 切句 / 写回 / 增删句 / 外部改盘重载**每条路径都必须走同一个刷新入口**。
  3. **`for` 与 `GridBox` → 触发条件：把 `for` 直接当 `GridBox` 单元格。** 若遇到 `RepeatedItemTree::grid_layout_input_data() not implemented for …` 的 debug 日志或该处布局异常，把 `for` 包进独占的 `HorizontalBox`/`VerticalBox`、跨列显式 `colspan` 即可。**但要澄清：1.17.1 并非"不支持"** —— 编译器会为 repeated component 生成实现（`i-slint-compiler-1.17.1/generator/rust.rs` 的 `grid_layout_input_for_repeated` 分支生成 `grid_layout_input_data`），`i-slint-core-1.17.1/model/repeater.rs` 里那句 "not implemented" 只是默认实现的 `debug_log!` 兜底（**不 panic、不"运行时崩"**）。所以写法是"若遇该报错则…"，而不是"绝对不能用"。
- **Rust 侧职责**：工程状态机（句子状态/seed/时间轴）、服务调用（HTTP + base64）、文件落盘、音频拼接。**大函数/Slint 映射逻辑放 Rust**，避免 slint-build 在 Windows 下栈溢出。
- 线程与 UI：合成在后台线程，UI 更新必须走 `upgrade_in_event_loop`（`Weak::upgrade` 仅创建线程可用）；`invoke_from_event_loop` 的闭包要求 `Send`，不要往里塞 `Rc`。

### 5.2 与现有 Python 工具的关系与边界

| 组件 | 角色 | 与产品界面的边界 |
|---|---|---|
| `config/models.schema.yaml` | **唯一事实源**：场景定义、模型旋钮、`known_issues`、`product_excluded`、文本规则 | 界面**不复制**这些决策，只读并渲染；模型管理抽屉显示的就是它的内容 |
| `tools/audio_config.py` | 配置层引用实现：渲染 `server.json`、文本兜底（规范化 + 词典）、按场景执行 | **文本层的算法必须以此为准**（`normalize()` / `verbalize()` / `apply_dictionary()`）；Rust 侧要么调它、要么逐条对齐并写等价测试，不允许两份实现各写各的 |
| `tools/audio_dub.py` | 配音链路参考实现：切句、逐句合成、拼装、单句重录、`project.json` 结构、落盘不变式（`write_atomic` / 拼装前校验——**`fix/text-layer-and-dataloss` 实现，随本轮合并进入 main**） | **Rust 状态机的行为基线**：`project.json` 的字段（`sentences[].text/spoken/seed/wav/duration/start/status`）直接沿用，保证 CLI 与界面能开同一个工程；M1 加 `id` 时两边同步 |
| `tools/audio_eval.py` | 评估台：可懂度/耗时/峰值内存 + 回归对比（TRICKY 用例集含"数字-紧凑"无空格形态——用例由 `fix/text-layer-and-dataloss` 补入、`fix/eval-tn-convergence` 收进默认 `--texts`） | 产品**不重复实现评估**；界面上"质量自检"按钮就是调它；每次换配置/换量化档后跑一遍 |
| `audio.cpp`（**独立仓库 checkout，当前 v0.7.3**） | 引擎与服务（`audiocpp_server`，`127.0.0.1:8080`） | 适配只写在本仓库薄层，滞后上游 1~2 版；**submodule 化待落**（本仓库当前既无 `.gitmodules` 也无 `external/`，引擎是本机另一处 checkout）；上游接口变了改我们这层 |
| 上游文本规范化 | 模型侧 TN（`engine` 策略） | 模型已接 TN 的（如 index-tts2）**不重复处理**，避免双重转换 —— 这由配置的 `text_overrides.normalization` 决定，不写死在代码里 |

### 5.3 性能与资源预算（来自 CHARTER 第 7 节实测）

- **合成耗时（挂钟时间是下界）**：配音按 **RTF 2~4** 估：5 分钟成品（300s 音频）纯合成 **10~20 分钟**；而 RTF 2~4 是**单句短文本**实测，90 句串行产线还要叠加模型加载/内存守卫/逐句落盘 → **重叠（边合成边校听）只压人工投入，不缩短关键路径**。因此 M0 标准是**条件式**："**人工投入 <10 分钟 / 出片 ≤ 纯合成时间 ×1.2**"（CHARTER §2 第 3 条）：**"出片 ≤20 分钟"是硬阈值但 RTF≈4 端不可达**（纯合成就 ≈20 分钟），必须 **M0 拿真实 5 分钟稿量跑一次端到端把 RTF 与挂钟两个数字量出来后再定标**。增量通道：`audio8-tts-stream`（0.6B，未 `product_excluded`）走 `/v1/audio/speech/live`，首句先出音频。
- 峰值内存 **2.3~4.1G**：`max_loaded_models: 2` 是创作者机器的保守值；跑评估台（需要额外 ASR 模型）前先卸 TTS。
- 歌曲线 2'48" 需 8 分钟（yue2，RTF 2.86）/ 120s 需 6.4 分钟（ace-step，RTF 3.2，**每单位音频更慢**）——这是它降级为彩蛋的直接原因。
- 界面不阻塞：合成的 HTTP 超时是 1800s（长句 + 慢机器），UI 必须全程可交互、可取消。
