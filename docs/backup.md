# 一键备份（M4-P8 的一半）

> 产品口径：`docs/product-plan.md` §4.2 的 P8「自动更新与备份」。
> **本文件只描述"备份"这一半；"自动更新"不在本批**（边界见文末）。

## 它解决什么

用户的资产全部散在应用数据目录 `~/Documents/音频作坊/` 下：

```text
~/Documents/音频作坊/
  projects/        # 工程、逐句音频、成品、人声分离两轨…（最大的一块）
  settings.json    # 服务地址/端口、模型目录、BGM 输入、启用的词典
  templates.json   # 配音模板
  dictionaries/    # 发音词典库（多套）
  voices/          # 音色库（含参考音频副本）
```

跑过的工程越多，这份目录越值钱，而它**没有任何备份入口**——误删、换机、磁盘坏就是全丢。
一键备份就是把这五类东西**复制**成一份自包含的目录。

## 怎么用

设置抽屉 → 「备份」→「一键备份…」→ 选一个目标目录（外置盘/同步盘/另一个卷都行）。

结果写成：

```text
<你选的目标目录>/
  音频作坊备份-20260917-143012/
    projects/…
    settings.json
    templates.json
    dictionaries/…
    voices/…
    manifest.json          # 这份备份装了什么：条目数、文件数、字节数、跳过项
```

状态行会如实报告「已备份 N 个文件（X MB）到 <路径>」；有跳过项时会一并说出第一项。

## 三条硬保证

1. **源文件一个都不动**。备份是复制，不是搬迁；源目录在备份前后逐字节一致（单测断言）。
2. **中断不会被当成完成**。整个过程先写在 `.部分-<时间戳>-<n>/`，**全部成功后才 `rename`** 成
   `音频作坊备份-<时间戳>`。中途崩溃/拔盘/强退留下的只会是 `.部分-` 前缀的目录，一眼能认出不是备份。
3. **不复用、不覆盖**。同一个时间戳再备一次会顺延成 `…-2`、`…-3`，绝不覆盖上一份。

## 单项失败是隔离的

- 单个文件读不了（权限/坏道）：**记进 `skipped` 并继续**，不让一个坏文件拖垮整份备份；
  状态行与 `manifest.json` 都会如实列出。
- **符号链接一律跳过**（记进 `skipped`）：备份不做软链跳转，否则会顺着链接把外部目录整棵拖进来，
  或把指向外部的链接原样带进备份、换机后指向不存在的东西。
- 目标目录若落在源目录里面（例如"把备份放进 `projects/`"），**直接拒绝**——否则备份会把自己的产物
  再复制进去，递归自吞。

## 怎么还原

把 `音频作坊备份-<时间戳>/` **里面的内容**（不是这一层目录本身）放回 `~/Documents/音频作坊/`，
覆盖同名项即可。备份目录是自包含的，不依赖源目录仍然存在。

> 还原前建议先把手头这份 `~/Documents/音频作坊/` 也备一次（或整体改名留档），免得覆盖掉比备份更新的东西。

## 明确不含什么（边界）

- **不含本应用自身**（可执行文件/资源），也不含 audio-service 服务端的模型权重——模型按
  `docs/product-plan.md` §4.3 的规定**不打进发行版也不进备份**，换机后重新下载。
- **不含自动备份/定时备份**：本批只有一个手动入口，不后台跑、不驻留。
- **不含自动更新**：P8 的另一半（检查新版本/下载安装包）单独一批，不在这里夹带。

## 实现位置

- 纯逻辑 + 文件操作：`src/backup.rs`（`backup_all` / `BackupSummary` / `human_bytes`），单测在同一文件里。
- UI 接线：`src/main.rs`（设置抽屉的「一键备份…」按钮、后台线程、消息处理）。
